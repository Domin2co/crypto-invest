# Crypto Invest 로컬 기능 테스트 가이드

- 문서 버전: 2.8
- 기준일: 2026-09-25
- 갱신 기준: 화면, API, 실행 절차 또는 환경 설정이 바뀔 때 이 문서와 PDF를 함께 갱신합니다.

## 실행 구성

- Frontend: `http://127.0.0.1:5173`
- Backend: `http://127.0.0.1:8080`
- Frontend의 `/api/*` 요청은 Vite 개발 서버가 Backend 8080으로 전달합니다.
- 모의거래는 별도 메뉴와 가상 지갑을 사용합니다. 실주문은 안전 설정에서 기본 차단되어 있습니다. 테스트 중 실제 주문이나 출금을 실행하지 마세요.

## 준비

프로젝트 루트는 `C:\dev\crypto-invest`입니다. Docker Desktop, JDK 21, Node.js 24 이상을 준비하고 루트 `.env`가 있어야 합니다.

```powershell
Copy-Item .env.example .env
```

`.env`에 PostgreSQL 비밀번호와 Base64 32-byte `AUTH_TOKEN_SECRET`, `CREDENTIAL_ENCRYPTION_KEY`를 설정합니다. 로컬에 기존 `.env`가 있다면 덮어쓰지 말고 그대로 사용하세요. 키 값을 공유하거나 로그에 남기지 마세요. DB에 거래소 credential을 저장한 뒤 암호화 키를 바꾸면 기존 credential을 복호화할 수 없습니다. `.env`는 Git에서 제외됩니다.

## 1. DB와 Backend 시작

첫 PowerShell 창에서 프로젝트 루트로 이동한 뒤 실행합니다.

```powershell
docker compose up -d
docker compose ps
```

PostgreSQL과 Redis가 `healthy`인지 확인합니다. 같은 창에서 `.env` 설정을 프로세스에 불러오고 백엔드를 시작합니다. 키 값은 출력되지 않습니다.

```powershell
Get-Content .env | ForEach-Object {
  if ($_ -match '^\s*([^#=]+)=(.*)$') {
    $envName = $matches[1]
    $envValue = $matches[2]
    Set-Item -Path "Env:$envName" -Value $envValue
  }
}
Set-Location backend
$env:JAVA_HOME = 'C:\dev\jdk-21.0.12.1'
.\gradlew.bat bootRun --console=plain
```

시작 로그에서 `Started CryptoInvestApplication`, Flyway schema version 24를 확인합니다. `http://127.0.0.1:8080/api/health`는 `status: UP`, `liveOrderSubmissionEnabled: false`를 반환해야 합니다. Backend 로그에는 method, 경로, 상태 코드, 처리 시간만 남고 Authorization, query string, 본문은 기록되지 않습니다. 서버를 종료할 때 `Ctrl+C`를 누릅니다.

## 2. Frontend 시작

두 번째 PowerShell 창에서 실행합니다.

```powershell
Set-Location C:\dev\crypto-invest\frontend
npm run dev -- --host 127.0.0.1
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 상단 메뉴에서 대시보드, 실거래, 모의거래, 포트폴리오, 시장, 추천, 거래 이력이 각각 별도 화면인지 확인합니다. 로그인 상태에서는 마이 페이지와 로그아웃이 상단에 표시됩니다. 개인정보 처리방침 링크는 페이지 아래에서 열 수 있습니다.

## 3. 가입과 로그인

1. `로그인 / 회원가입`을 눌러 `/account`로 이동합니다.
2. `회원가입` 탭에서 테스트 이메일과 대문자·소문자·숫자·특수문자가 포함된 10~20자 비밀번호를 입력하고 이메일 인증을 완료한 뒤 필수 개인정보 처리 동의를 선택합니다. 마케팅 동의는 선택입니다.
3. 가입 뒤 닉네임 설정 화면에서 2~8자의 한글 완성형·영문·숫자로 닉네임을 만들고 `중복확인` 후 저장합니다. 공백, 특수문자, 자음/모음 단독 문자는 사용할 수 없습니다. 닉네임을 저장하기 전에는 다른 메뉴와 보호 API에 접근할 수 없습니다.
4. 닉네임 수정도 새 닉네임마다 중복확인이 필요합니다. 마이 페이지의 `내 정보 수정` 화면에서 비밀번호 변경과 이메일 변경을 할 수 있습니다. 이메일은 새 주소 인증 후 가입/변경일부터 90일이 지나야 수정할 수 있습니다.
5. 닉네임이 이미 등록된 계정으로 로그인하면 대시보드로 이동합니다. 로그인 토큰은 현재 탭의 sessionStorage에 보관됩니다. 상단에 남은 시간이 표시되고 30분 연장 버튼으로 현재 토큰이 살아있는 동안 새 30분을 연장할 수 있습니다. 만료되면 자동으로 로그아웃 화면으로 이동합니다. 첫 배포 후에는 기존 토큰이 폐기되므로 한 번 다시 로그인해야 합니다. F5 뒤에도 세션은 복원되며 로그아웃하면 토큰이 지워집니다.

가입/로그인 API는 브라우저의 `/api/auth/register`, `/api/auth/login` 요청으로 보이고 Vite가 Backend로 전달합니다. 이전의 409 `INVALID_STATE` 문제는 기동 시 인증 키 검증으로 바뀌었습니다. 키 설정이 잘못되면 Backend가 원인을 로그에 남기고 기동을 거부합니다.

## 4. 시장·차트 확인

데스크톱 거래 화면에서는 차트와 실시간 체결이 호가 위에 전체 너비로 표시됩니다. 그 아래에서는 호가와 주문 메뉴를 나란히 확인할 수 있습니다. 호가창은 매도·매수 가격대를 현재가 기준 위·아래로 분리하고 양쪽 15단을 정렬합니다. 처음 호가가 오면 현재가 위·아래 8단이 보이며, 사용자가 스크롤한 위치는 잔량 변경 뒤에도 유지됩니다. 일반호가는 가격대별 잔량, 누적호가는 최우선 호가부터 해당 가격까지 합산한 잔량을 표시하며 잔량 막대도 해당 모드의 값에 맞춰 비교합니다. 일반호가/누적호가와 주문 탭은 선택된 항목에 체크와 진한 배경을 표시합니다. 작은 화면에서는 영역이 위에서 아래로 배치됩니다.

시장·실거래·모의거래 화면에서 거래소를 고르고 코인 검색란에 심볼이나 한글/영문 이름을 입력합니다. 목록은 선택 거래소의 KRW 마켓 전체를 조회합니다. 검색란에 심볼, 한글명, 영문명을 입력할 수 있고, 거래소를 바꾸면 해당 거래소에만 상장된 종목도 목록에서 선택할 수 있습니다. 두 거래소 가격 카드를 눌러 거래소를 바꾸어 비교할 수 있습니다.

- 캔들 간격: 1·3·5·10·15·30분, 1·4시간, 일·주·월
- 차트 형태: 캔들, 선, 영역
- 마우스 휠 또는 모바일 두 손가락 동작으로 차트를 확대·축소합니다. 안내는 한 번 표시되며 닫을 수 있습니다.
- 차트 아래 안내를 닫은 뒤 휠을 사용해도 페이지 스크롤은 움직이지 않고 차트만 확대·축소되는지 확인합니다.
- 차트 아래에는 거래소별 최근 7일 일봉의 일자, 종가, 전일 대비율, 거래량이 표시되고 종목 토론방과 충분한 간격을 둡니다. 토론 글은 로그인과 닉네임 설정 후 작성하며 민감정보를 게시하지 마세요.
- 실시간 체결 행은 시각·가격·체결량이 고정 폭 열에 정렬되고, 체결량은 소수점 넷째 자리까지 표시합니다.
- 지표: SMA 7/SMA 30 표시 선택, RSI(14) 및 선택 기간 변화
- 캔들 위에 포인터를 두거나 방향키로 이동하면 해당 시각의 시가·고가·저가·종가·거래량을 확인할 수 있습니다.
- 호가: 매도 호가는 높은 가격부터 최우선 매도 가격까지, 매수 호가는 최우선 매수 가격부터 낮은 가격 순서로 표시합니다. 일반호가는 각 가격의 잔량을, 누적호가는 최우선 가격부터 해당 단계까지의 합산 잔량을 보여줍니다. 매도·매수 가격에는 당일 시가 대비 등락률을 표시합니다. 모의거래에서는 호가 가격과 방향이 주문 입력에 반영되고 즉시 체결 가능한 경우만 가상 체결합니다. 실거래에서도 선택 가격으로 IOC 지정가를 구성하며 기본 잠금과 모든 안전 검증을 통과해야 제출됩니다. 두 경우 모두 미체결 잔량은 대기 주문으로 보관하지 않습니다.
- 호가의 각 행은 어두운 UI에 맞는 얇은 구분선으로 나뉩니다. 스크롤바는 평소 숨겨지고 스크롤하는 동안에만 얇게 나타나는지 확인합니다.
- 실시간 시장 체결은 공개 시장 전체의 체결입니다. 내 주문 내역과는 분리되어 있습니다.

가격·체결·호가는 거래소의 공개 WebSocket, 과거 캔들과 코인 목록은 Backend 공개 API에서 조회합니다. 지표는 참고 정보이며 추천이나 주문 신호가 아닙니다. 코인이 한 거래소에만 상장된 경우 반대쪽 거래소 가격은 표시되지 않을 수 있습니다.

## 종목 토론방 상세와 계정 수정

1. 시장 화면에서 코인을 선택하고 토론 글을 작성합니다. 제목과 내용을 입력한 뒤 글꼴, 크기, 정렬을 바꾸고 512KB 이하 PNG/JPEG/WebP 이미지를 첨부해 등록합니다.
2. 목록에는 글번호, 제목, 작성자, 작성일, 추천수만 표시되는지 확인합니다. 제목을 열어 저장한 본문 서식과 이미지가 보이고, 목록에서는 본문이 노출되지 않는지 확인합니다.
3. 로그인 상태에서 댓글과 추천/비추천을 등록합니다. 한 사용자 표시는 하나만 유지되며 반대 방향을 선택하면 기존 표가 바뀝니다. 비추천 21개 이상인 글은 본문과 이미지가 가려지고 그래도 내용 보기 선택 후에만 나타납니다.
4. 상세 글 아래 종목 거래 화면 버튼과 글 목록을 확인합니다. 현재 글 항목은 다시 열 수 없는 현재 글 표시로 나타납니다.
5. 마이 페이지에서 내 정보 수정 버튼을 눌러 별도 화면으로 이동합니다. 닉네임 변경은 매번 중복확인 후 저장하고, 비밀번호 입력의 눈 모양 버튼이 필드 안에 있는지 확인합니다.

## 5. 매수·매도·간편주문·거래내역

모의거래 화면의 주문 카드에서 `매수`, `매도`, `간편주문`, `호가주문`, `거래내역` 탭을 확인합니다. 간편주문은 금액 버튼을 골라 예상 수량을 확인한 뒤 실행합니다. 일반 매수/매도 입력과 같은 가상 지갑 및 주문 API를 사용합니다. 모의 주문은 실제 거래소에 전달되지 않습니다. 거래내역 탭에는 로그인한 사용자의 모의 체결만 표시됩니다.

실거래 화면은 같은 다섯 탭과 시세·호가를 제공하지만, 기본 설정의 실주문은 잠겨 있습니다. 호가를 선택하면 지정가 IOC 주문을 구성하며, 허용된 환경에서만 최종 확인과 서버 위험 검증 뒤 제출합니다. IOC 미체결 잔량은 거래소에서 즉시 취소됩니다. 거래내역은 로그인 계정 소유의 로컬 실주문 감사 이력만 읽습니다. 주문 입력·제출은 enable, kill switch 해제, 일일 한도, 사용자 재확인, 거래소 잔고 및 RiskEngine 검증을 모두 통과해야 합니다. 기능 테스트에서는 실주문을 활성화하지 마세요.

모의거래 아래에서 거래소별 지갑, 포트폴리오 비중, 월간 대회와 메달을 확인할 수 있습니다. 대회 공개와 참가 신청은 별도 선택 동의를 요구합니다. 취소하면 공개 기록이 삭제됩니다.

## 6. 나머지 기능과 검증

- 시장: 로그인이나 API key 없이 거래소별 공개 시세를 확인합니다.
- 추천: 점수, 계산 근거, 데이터 시각 및 위험·한계를 봅니다. 추천은 주문 지시가 아닙니다.
- 포트폴리오: 계정 화면에서 거래소 읽기 전용 API key를 연동해야 실잔고를 조회할 수 있습니다. 출금 권한은 설정하지 마세요.
- 개인정보: 계정 화면에서 동의 이력·철회·계정 삭제를 확인합니다.
- 월간 대회는 한국시간 월 경계의 평가액으로 집계됩니다. 월 시작/종료 시점에 Backend와 시세 조회가 오래 중단되면 이전 잔고를 재구성할 수 없어 집계가 미완료일 수 있습니다.

Frontend 검증:

```powershell
Set-Location C:\dev\crypto-invest\frontend
npm run lint
npm run typecheck
npm run test
npm run build
```

Backend와 DB를 실행한 상태에서 Browser E2E:

```powershell
Set-Location C:\dev\crypto-invest\e2e
npm run test:e2e
```

## 종료와 문제 해결

Backend와 Frontend 창에서 각각 `Ctrl+C`를 누릅니다. DB와 Redis를 중지하려면 루트에서 `docker compose stop`을 사용합니다. `docker compose down -v`는 DB 데이터를 지울 수 있으므로 사용하지 마세요.

- **회원가입이 실패:** Backend 프로세스에 .env가 반영됐는지 확인합니다. 키는 로그나 채팅에 붙이지 않습니다.
- **로그인이 실패:** 가입 시 사용한 이메일과 비밀번호를 확인합니다.
- **Backend 연결 오류:** Backend가 8080에서 실행 중인지 확인하고 /api/health를 엽니다.
- **거래소 credential 저장 실패:** CREDENTIAL_ENCRYPTION_KEY가 Backend 프로세스에 설정됐는지 확인합니다.
- **DB 연결 실패:** docker compose ps와 .env의 DB 설정을 확인합니다.
- **시장 데이터 조회 실패:** 인터넷 연결, 선택 거래소 상장 여부, Backend 로그를 확인합니다.
- **8080 포트 사용 중:** 기존 Backend 프로세스를 종료한 뒤 다시 실행합니다.



## 가입 이메일 인증 및 계정 보안

1. 개발 환경에서 `docker compose up -d mailpit`을 실행하고 Backend는 프로젝트 `.env`를 환경 변수로 전달해 실행합니다. Mailpit 받은 편지함은 `http://127.0.0.1:8025`입니다.
2. 회원가입 화면에서 이메일 인증 코드를 요청하고 Mailpit에서 받은 6자리 코드를 확인한 뒤 가입을 완료합니다. 코드는 10분 동안 유효하며 재요청은 60초 후 가능합니다.
3. 비밀번호는 가입/변경 시 10~20자, 대문자·소문자·숫자·특수문자를 포함해야 합니다. 로그인은 이 형식 제한 없이 비밀번호를 받습니다. 눈 모양 버튼으로 입력값 표시 여부를 바꿀 수 있습니다.
4. 마이 페이지에서 현재 비밀번호를 확인해 새 비밀번호를 변경할 수 있습니다. 이메일은 새 주소 인증 후 변경하며, 가입 또는 마지막 변경으로부터 90일이 지난 뒤에만 가능합니다.
5. 운영 배포에는 Mailpit 대신 실제 SMTP 호스트, 포트, 인증 계정, TLS 설정과 발신 주소를 비밀 환경 변수로 제공해야 합니다.

## 새로고침 후 로그인 유지

로그인한 같은 브라우저 탭에서 F5를 누르면 인증 토큰을 탭 세션 저장소에서 복원하여 현재 경로를 다시 엽니다. 로그아웃하면 토큰이 지워집니다. 탭을 닫으면 탭 세션이 종료됩니다. 토큰은 발급 후 30분에 만료되며 상단에 남은 시간이 표시됩니다. 현재 유효한 토큰으로 30분 연장 버튼을 누르면 새 30분 토큰을 발급합니다. 만료되면 자동 로그아웃됩니다. 30분 이전에 발급된 기존 토큰은 새 토큰 형식 도입 시 폐기되어 재로그인이 필요합니다.

## 종목 토론방 수정·신고 기능

게시글 상세에서 작성자는 수정/삭제할 수 있고 댓글 작성자에게는 댓글 수정/삭제가 표시됩니다. 댓글은 한 페이지에 10개씩 이동할 수 있습니다. 다른 사용자의 수정 요청은 서버가 거절합니다. 로그인한 사용자는 신고 사유를 골라 신고할 수 있습니다. 관리자 계정은 상단 메뉴의 관리자 페이지에서 토론방 신고 관리를 열어 신고를 검토하고 숨김, 기각, 복원을 수행합니다. 서버도 각 관리자 API 요청마다 ADMIN 역할을 검사합니다. ADMIN 역할은 공개 화면에서 지정되지 않으며 운영자가 별도 권한 절차로 부여해야 합니다.

## Password reset and monthly PAPER recovery

- From the login form, open password reset, request an email code, verify the code, and set a new password. Confirm the old password no longer works and sign in with the new password. Existing sessions are revoked immediately after reset.
- Local reset/signup emails are visible in Mailpit at `http://127.0.0.1:8025`.
- For the monthly PAPER league, confirm the opening snapshot timestamp appears in the board and that participant fills remain blocked while the opening snapshot is pending. Delayed snapshots display their actual capture time.
- Production email uses the `production` Spring profile and authenticated STARTTLS. Provider account, verified sender domain, DNS records, and secret values must be configured manually before delivery.
